# metrics-collector-selection

This fixture covers the selectable collector contract without applying Helm releases. The fixture itself requires Terraform >= 1.7 because it uses native `terraform test` and provider mocking; the production module remains compatible with Terraform ~> 1.3.

The focused test responsibilities are:

- `2-root-contract.tftest.hcl`: root selector, validation, status, and datasource contract;
- `3-operator-values.tftest.hcl`: Operator chart and protected-values contract;
- `4-generated-objects.tftest.hcl`: VMAgent, VMServiceScrape, inline, and storage contract.
- `5-native-stack.tftest.hcl`: independent node-exporter, native node/component
  scrapes, and complete VictoriaMetrics-only integration contract.

The native Terraform tests use mocked Grafana, Helm, Random, and Time providers.
To run them:

```sh
cd tests/metrics-collector-selection
terraform init -backend=false -lockfile=readonly
terraform test
```

The final contract covered by this fixture is:

- both collector backends may be installed, while `metrics_collector` selects the only active scraper and default Grafana datasource;
- VictoriaMetrics-only mode installs official Operator CRDs first, then a dependent release containing VMAgent and native scrape resources;
- dual-backend VictoriaMetrics mode may convert application `PodMonitor`/`ServiceMonitor` resources while migration is in progress;
- Prometheus mode keeps the Prometheus monitor path and generates no native VictoriaMetrics KSM object or VMAgent;
- kube-state-metrics and node-exporter are independent releases and are not owned by the Prometheus release;
- native kubelet/cAdvisor discovery and collector-aware Tempo/Loki/Grafana integration remain valid without Prometheus CRDs;
- there is no standalone VictoriaMetrics agent Helm release or generated static KSM scrape job;
- VictoriaMetrics mode requires only `victoria_metrics.enabled = true`; Prometheus is optional;
- caller-owned scrape jobs are preserved exactly, including the transition case where a caller supplies a `kube-state-metrics` job;
- the monitor-conversion boundary verifies converter ownership/watch settings and verifies that no application credentials or authorization config is generated by this module. Live rollout checks must separately verify that source and converted monitors retain the same authorization type and Secret name/key selector without exposing Secret values;
- paired storage regression runs preserve VictoriaMetrics cluster release identity, retention, vmstorage replicas, storage class, size, and access modes with the agent disabled and enabled.

The credential-boundary scan must remain clean:

```sh
cd ../..
if rg -n -i '^variable "[^"]*(token|secret|credential|authorization)[^"]*"' modules/victoria-metrics/variables.tf; then
  echo "Application credential inputs must not be declared by the VictoriaMetrics module."
  exit 1
fi
```

Payload keys such as `credentials` and Secret selector fields are valid. This gate only forbids application credential inputs in the module variable declarations; it does not inspect payload values or source-monitor selectors.

Run the complete focused suite from this directory with:

```sh
cd tests/metrics-collector-selection
terraform test
```
